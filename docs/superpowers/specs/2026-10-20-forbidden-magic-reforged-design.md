# Forbidden Magic для Thaumcraft 4: Reforged — проект

Статус: форма согласована в чате 2026-10-20; 2026-10-21 выбран полный объём §5.1. Веха B
(аспект-слой и одна сквозная тема) — первый этап, а не граница поставки. Установка: одним jar'ом,
если автор хоста примет аддон-аспект-API; иначе — патчер поверх серии патчей.
Цель: Minecraft 26.3 / NeoForge 26.3.0.57-beta / Java 25, аддон к Thaumcraft 4: Reforged, ветка `main`
Источник поведения: Forbidden Magic 0.574 для Minecraft 1.7.10 (`ForbiddenMagic/`, WTFPL)

## 1. Цель

Портировать Forbidden Magic как аддон к Thaumcraft 4: Reforged, сохранив контент, числа, рецепты,
тексты исследований и ассеты оригинала как норму — по той же доктрине, по которой сам хост переносит
Thaumcraft 4.2.3.5. Контент, требующий сторонний мод, которого нет под этим загрузчиком и версией,
вырезается и документируется, а не изобретается заново.

Порт — один проект в одной новой папке. Рабочее дерево хоста во все моменты побайтово совпадает с
клоном upstream; это обеспечивается гейтом в сборке, а не дисциплиной.

## 2. Ограничения

- **Принадлежность и лицензия хоста.** Репозиторий Thaumcraft 4: Reforged принадлежит `notlikethiss`.
  Файла `LICENSE` нет, объявлено `mod_license=All Rights Reserved`, в `README.md:9` сказано
  «Personal use only … not intended for redistribution». Поэтому правки хоста разрабатываются локально
  и предлагаются upstream; собранный jar хоста этот проект не публикует никогда.
- **Аддон-API хоста — не контракт стабильности.** Поверхность для аддонов описана в разделе
  `CLAUDE.md` «API для аддонов», а это файл инструкций собственным агентам хоста, не обещание
  совместимости. Каждая версия хоста пинится коммитом по sha.
- **Оригинальный Forbidden Magic под WTFPL.** Его код и 135 текстур можно копировать и изменять.
  Порт распространяется под MIT; WTFPL оригинала, ARR хоста и происхождение ассетов фиксируются
  в `NOTICE`.
  Ресурсы и код Thaumcraft к себе не переносим: где оригинальный FM ссылается на пути
  `thaumcraft:`, они разрешаются из хоста в рантайме.
- **Паритет.** Числа, стоимость аспектов, тексты исследований и форма рецептов берутся из исходника
  1.7.10 без правок. Любое отступление фиксируется в `docs/deviations.md` с причиной.
- **Атрибуция.** Порт публикуется как Forbidden Magic с оригинальным автором, этот репозиторий — как
  порт, Thaumcraft 4: Reforged и Azanor — в кредитах, с указанием, что разработка шла с участием ИИ.

## 3. Почему хост обязан измениться

Forbidden Magic регистрирует семь собственных аспектов — `luxuria`, `infernus`, `superbia`, `gula`,
`invidia`, `desidia`, `ira` — создаваемых через `new Aspect(tag, color, components, texture, blend)`.
На них держатся 16 рецептов, 16 записей исследования, 17 обращений в Клетке Гнева и вся идентичность
Осколков грехов.

В хосте `Aspect` — это `public enum` из 48 констант (`thaumcraft/aspect/Aspect.java:17`), путь текстуры
жёстко зашит в `thaumcraft:textures/aspects/<tag>.png`. Java не позволяет добавить константу enum
извне: конструктор приватен, `$VALUES` фиксирован, рефлективное создание бросает исключение.
`AspectList` ключуется `Map<Aspect, Integer>`, поэтому замена типа-представителя тоже не вариант.
В исходниках NeoForge 26.3 нет ни `IClassTransformer`, ни coremod-хука; `accesstransformer.cfg`
расширяет только видимость и не может перестроить класс.

Проверено по исходнику хоста, чтобы размер запроса был известен заранее:

| Измерено | Значение | Следствие |
|---|---|---|
| ссылок `Aspect.<КОНСТАНТА>` | 1827, из них 1379 в четырёх генерируемых файлах | генерированные таблицы не трогаем; обращение к `static final` сохраняет синтаксис |
| вызовов `Aspect.values()` | 17 в писаном коде плюс 2 тестовых файла | `static Aspect[] values()` оставляет все места вызова валидными |
| `switch` по аспекту | 2 в `wand/WandVis.java:32,44` (`get` и `with`) | переписываются на if-цепочки; `default` уже есть, поведение сохраняется |
| `Aspect.valueOf`, `isEnum`, `<E extends Enum>` | нет | скрытых enum-зависимостей нет |
| `aspect.ordinal()` | три места в `entity/AspectOrb.java`: `:41` (запись в синк-данные), `:54` (`builder.define(DATA_ASPECT, Aspect.AIR.ordinal())` — дефолт в провайдере), `:132` (запись при загрузке) | индекс реестра обязан быть стабильным и общим для всех трёх мест; закрывается GameTest |
| enum-специфичное внутри самого `Aspect` | `CODEC` через `StringRepresentable.fromEnum(Aspect::values)` (`aspect/Aspect.java:68`), обходы `values()` в `combine`, `getPrimalAspects`, `getCompoundAspects` | локализовано в одном файле; `fromEnum` типизирован под `Enum`, поэтому в классе кодек строится из `getSerializedName()`, а не `fromEnum` |

Итог: изменяются два файла (`aspect/Aspect.java`, `wand/WandVis.java`) плюс метод чтения индекса в
`entity/AspectOrb.java` и хук регистрации. В швы `platform/` изменение не заходит, поэтому гейт хоста
`tools/check_seams.py` не задевается.

## 4. Архитектура

### 4.1 Раскладка репозитория

```
forbidden-magic-reforged/

  patches/                  серия .patch, в гите, временный костыль и payload PR
  maven/                    локальный maven-репозиторий пропатченного хоста      (gitignore)
  src/main/java/dev/visfox/forbiddenreforged/     порт
```

`patches/` ведутся в гите, потому что они же идут приложением к upstream-запросу. Ни один
публикуемый этим проектом артефакт не содержит перекомпилированного класса хоста.

### 4.2 Серия патчей хоста

| Патч | Содержание | Объём |
|---|---|---|
| `0001-aspect-registry` | `Aspect`: enum → `final class` с реестром; `static final` константы в исходном порядке; `static Aspect[] values()` — встроенные, затем аддон-аспекты; `CODEC`/`STREAM_CODEC` через by-tag карту, в классе без `Enum` — из `getSerializedName()`; `ordinal()` снимается с класса и берётся из реестра, поэтому `AspectOrb` правится в четырёх строках (`:41`, `:54`, `:60`, `:132`); два `switch (aspect)` в `wand/WandVis.java` переписываются на if-цепочки; `image` принимает полный `Identifier`; публичный `Aspect.register(...)` | `aspect/Aspect.java`, `entity/AspectOrb.java`, `wand/WandVis.java`, ~250 строк |
| `0002-aspect-addon-init` | реестр `AddonAspects` и вызов в `AspectSync.rebuild` до `ModernAspects`; идемпотентен, поэтому аддон может инициализировать его и раньше, из common setup | ~35 строк |
| `0003-host-publish` | `maven-publish` на координаты `thaumcraft:thaumcraft:1.2`; публикуется как `thaumcraft-1.2.jar` | ~15 строк |

Пропатченный хост обязан иметь версию мода ровно `1.2`, а не `1.1` и не `1.2-fm.1`: пре-релизный
квалификатор сортируется ниже `1.2` и не удовлетворил бы диапазону, который объявляет порт.
`0001` и `0002` — те файлы, которые удалит будущий мерж upstream; `0003` остаётся локальной
инфраструктурой сборки и в upstream не предлагается.

`0004-taint-block-tag` сознательно отложен. Хост перечисляет восемь тaint-блоков руками
(`taint/TaintSpread.java:88-91` — метод `isTaintBlock`: `CRUSTED_TAINT`, `TAINTED_SOIL`,
`FLESH_BLOCK`, `FIBROUS_TAINT`, `TAINTED_GRASS`, `TAINTED_PLANT`, `SPORE_STALK`,
`MATURE_SPORE_STALK`), но требование Forbidden Magic — скруное дерево и скруный камень иммунны к
волокнистой скверне — выполнимо без патча, потому что распространение заражает только воздух,
заменяемые блоки и растительность. Если на инкременте 8 окажется, что иммунитет так не
достигается, патч добавляется тогда, а не заранее.

`tools/prepare_host.py` клонирует локальный хост на sha из `host.sha`, применяет серию и падает
на первом же хунке, который не лёг.

### 4.4 Два разных касания хоста, и их надо разделять

Измерено по оригиналу: **40 из 88 файлов Forbidden Magic импортируют `thaumcraft.common.*`**, то есть
внутренности TC 1.7.10, а не его API. В 1.7.10 у FM не было границы: он брал `Config`, `ConfigBlocks`,
`ConfigItems`, singleton `Thaumcraft`, `ItemWandCasting`, `ResearchManager`, `PacketHandler` и
`PacketAspectPool`, `BlockUtils`, `Utils`, `PotionThaumarhia`, `PotionWarpWard`, `ItemPrimalCrusher`,
`ItemAmuletVis`, `ItemWispEssence`, `Config.taintMaterial`, `Config.biomeTaintID`,
`Config.researchDifficulty`. В хосте пакета `thaumcraft.common` нет вообще: всё это спрятано за
`platform/`, `registry/` и `network/`, а `tools/check_seams.py` в CI хоста следит, чтобы и сама логика
хоста не выглядывала наружу. Значит каждый из сорока файлов на переносе переключается на шов — это
работа по переносу, а не архитектурная задача, но её объём надо знать до оценки срока.

| Внутренность 1.7.10 | Шов хоста, куда она становится |
|---|---|
| `config.Config`, `ConfigBlocks`, `ConfigItems` | `Config`/`StartupConfig` и `registry/ModBlocks`, `registry/ModItems` |
| `common.Thaumcraft` (singleton) | `thaumcraft.Thaumcraft` и соответствующий `platform/`-хелпер |
| `items.wands.ItemWandCasting` | `wand/WandRegistry`, `RodUpdate`, `platform/StackData` |
| `lib.research.ResearchManager`, `lib.network.playerdata.PacketAspectPool`, `lib.network.PacketHandler` | `research/ResearchManager` (публичные statics), `network/ModPayloads`, `platform/ModNetwork` |
| `lib.potions.PotionThaumarhia`, `PotionWarpWard` | `registry/ModEffects` |
| `items.equipment.ItemPrimalCrusher`, `items.ItemWispEssence`, `items.baubles.ItemAmuletVis` | `registry/ModItems` и `platform/Bauble` |
| `lib.utils.BlockUtils`, `lib.utils.Utils` | `platform/Registration`, `platform/Transfer`, соответствующие `world/`-хелперы |
| `Config.taintMaterial`, `Config.biomeTaintID` | свойства блоков и `taint/TaintBiomes` |

Второе касание — единственное, которое зависит от нашего патча: класс `FmAspects`. Зависимость
объявлена как `thaumcraft` в диапазоне `[1.2,)` — версию, которую просит upstream-запрос. Переход от
локального патча к релизному хосту поэтому равен: удалить `patches/0001`, `patches/0002`,
`patches/0003`, убрать `host/` из `prepare_host.py`, перенаправить репозиторий на опубликованный jar.
Ни один файл порта при этом не меняется. Это и есть условие выхода, не дающее проекту запереться на
форке.

Разница между этими двумя касаниями и есть причина выбранного объёма. В поставке B (секция 5.0)
внутренностей хоста касаются два файла — `ForbiddenRecipes` и `ForbiddenResearch`, и оба только через
`Config.researchDifficulty` и `ConfigBlocks`/`ConfigItems`; в полном порте — сорок.

### 4.5 Ресурсы и конвенции

Наследуются у хоста, потому что расхождение усложнило бы и бэкпорт, и будущий мерж:

- ресурсы делают python-генераторы в `tools/`; datagen не используется, `src/generated/resources`
  руками не правится;
- meta-варианты предметов и блоков 1.7.10 раскладываются на отдельные id и свойства blockstate по
  `id_map.json`, как это делает хост;
- lang: только `en_us` и `ru_ru`, формулировки оригинального FM сохраняются; ключи исследований идут
  по образцу `tc.research_name.<KEY>` / `tc.research_text.<KEY>`;
- Java: четыре пробела, без комментариев; Python: четыре пробела, двойные кавычки, `pathlib`, без
  комментариев;
- коммиты на английском, `feat:` / `fix:`, без строк соавторства;
- повторная генерация ресурсов не должна менять ни одного файла.

Отдельно про переносы строк: git на этой машине конвертирует LF→CRLF при коммите, а исходники хоста —
LF. Клон для `prepare_host.py` создаётся с `core.autocrlf=false`, в репозитории порта лежит
`.gitattributes`. Это закрывается на инкременте 0, иначе патчи начнут отваливаться молча.

## 5. Опись контента

### 5.0 Веха M1: аспект-слой и одна сквозная тема

Цель проекта — весь объём §5.1. Веха M1 заканчивается там, где порт доказывает всю цепочку, а не там,
где перенесён весь мод. В объёме M1:

- семь аспектов и **полная** таблица меток предметов и сущностей из `DarkAspects` — таблица механическая
  и именно она делает аспекты добываемыми, без неё аспект существует, но в рецепт не входит;
- Осколки грехов (`ItemDeadlyShard`, семь мета-вариантов → семь id: `wrath`, `envy`, `taint`,
  `pride`, `lust`, `sloth`, `greed` по `ItemDeadlyShard.java:19`) и отдельный съедобный
  Осколок Чревоугодия (`ItemGluttonyShard`, не вариант осколка грехов) — единственная тема
  оригинала, которая целиком определена аспектами грехов;
- конфигурация с оригинальным `no_lust`, чтобы путь «контента нет по причине» был проверен на живом
  предмете, а не в теории; это STARTUP-конфиг, потому что значение читается до регистрации, и на
  клиенте с сервером оно должно совпадать; рубильник действует как в оригинале: `luxuria` не
  регистрируется вовсе (`DarkAspects.java:28`), а не остаётся в реестре без меток;
- исследования: своя категория `FORBIDDEN` и записи, которые замыкаются на осколках и аспектах
  (несколько из 34, остальные — в `docs/roadmap.md`);
- рецепты: только те, что потребляют осколки (в оригинале осколки рецептами не производятся;
  несколько из 21 core-рецепта, остальное — `docs/roadmap.md`);
- каркас сборки: `prepare_host.py`, серия патчей, локальный maven, генератор ресурсов,
  `check_provenance.py`, game test-ы.

Критерий «доказана вся цепочка» формулируется одной game test-сценой: `infernus` берётся из
netherrack, запись исследования про осколки открывается, осколок Гнева выпадает с убитого игроком
моба по правилам оригинала (`FMEventHandler.java:164-230`; в оригинале осколки не крафтятся вовсе),
а рецепт, который их потребляет, замыкается на зарегистрированные id; аспект при этом корректно
виден в Таумономиконе и JEI на клиенте. Если этот проход зелёный, дальше остаётся перенести контент
§5.1 — это вопрос времени, а не неизвестной архитектуры.

- block entity Клетки Гнева, её логика спавнера и рендерер, с расчётом геометрии в собственном
  аналоге `client/geom`; ПКМ клеткой с кристаллом моба в руке назначает моба
  (`BlockWrathCage.java:54` → `setMobID`), поэтому кристалл и клетка переносятся парой;
- генерация скруного дерева в скруных биомах, житель-еретик и его трейды;
- конфиг, включая оригинальный рубильник `no_lust`, сохранённый как **STARTUP**, а не SYNCED:
  значение читается до регистрации аспектов, поэтому клиент и сервер обязаны иметь одинаковое значение.
  При включении аспект `luxuria` не регистрируется, как в `DarkAspects.java:28`; остальные core-рубильники:
  `gluttony` 0/1/2, `enchanting`, `wrathCage`/`wrathCost`/`wrathEff`/`wrathCrazy`, `hereticID`, `tagResearch`.

### 5.2 Вырезано, с причиной в `docs/dropped.md`

- `compat/` целиком: Blood Magic, Botania, Ars Magica 2, CoFH, Thaumic Tinkerer — ничего этого нет под
  NeoForge 26.3;
- `ItemBloodRapier`, `DarkPotions` и оба эффекта зелий — API Blood Magic;
- `ItemBloodwell` и `ItemBoundwell` с их рецептами и исследованиями — Blood Magic (`blood bucket`,
  `BindingRegistry`); core-склянки `ItemCrystalwell` и `ItemPrimewell` остаются в порту;
- `ItemDivineOrb` (Божественная сфера) — Blood Magic: реализует `IBloodOrb`, `IBindable`, зовёт
  `SoulNetworkHandler` и `AltarRecipeRegistry`; без BM класс не загружается;
- четыре Botania `SubTile` (bloodthorn, euclidaisy, tainthistle, whisperweed);
- `ItemSubCollar` — Botania, а не Thaumic Tinkerer: `items/baubles/ItemSubCollar.java:25,31` тянет
  `vazkii.botania.api.item.ICosmeticAttachable` под `@Optional.Interface(modid = "Botania")`, поэтому
  покрывается пунктом про `compat/` выше и отдельной строки не заслуживает;
- `ItemMobCrystal` из вырезанного убран: он ядровой, а не зависимость. `items/ItemMobCrystal.java`
  лежит в `fox.spiteful.forbidden.items`, в импортах нет ни одного стороннего мода — только
  `fox.spiteful.forbidden.*`, `net.minecraft.*`, `thaumcraft.api.aspects.Aspect`, `cpw.mods.fml`.
  Связь с Thaumic Tinkerer во всём моде держат четыре файла интеграции — `DarkEnchantments`,
  `compat/Compat`, `Forbidden`, `Config`: флаг `Config.tt` и строка `after:ThaumicTinkerer`, — но не
  предметы. Кристалл задействован в семи файлах ядра: регистрация, исследование, рецепт,
  инициализация, обработчик событий и `BlockWrathCage`, который без него не назначает моба, так что
  вырезание ломало бы Клетку Гнева молча;
- обновления стержней жезлов blood и mana, читающие ресурсы Blood Magic или Botania;
- сторонние meta-варианты внутри `ItemResource`, `ItemWandCaps`, `ItemWandCores`. Классы остаются,
  варианты вырезаются. Точный список пишется в `docs/dropped.md` на инкременте 2, когда каждый вариант
  будет привязан к предмету-поставщику: зарегистрировано 27 имён, а происхождение по модификатору в
  исходнике 1.7.10 не подписано, так что заранее вставлять непроверенный список в проект нельзя;
- `plans.txt` не реализуется никогда: это незавершённый список идей оригинального автора, включая
  связывание демонов и грешных пчёл.

### 5.3 Вне объёма пока

Бэкпорт на `mc/1.21.1`. Мишень реальная — хост публикует релиз `1.21.1`, — но upstream-запрос должен

## 7. Риски

- **Ответ upstream от нас не зависит.** Мейнтейнер закрывает issue за день и мержит PR, сделанные
  ИИ-агентами, но внешний PR, открытый 19 октября, до сих пор без комментариев. Меры: запрос и PR
  готовятся из рабочей серии патчей; вариант с заменой аспектов на существующие просчитан и не
  отвергается.
- **Праймальные аспекты аддона ломают жезл.** `Aspect.getPrimalAspects()` — это шесть стихий, и хост
  использует его как список vis-слотов жезла. Аспект аддона без компонентов попадает в этот список:
  проверено 2026-10-21, праймальный probe уронил 14 тестов инфузии и жезла, составной — нет. Все семь
  аспектов FM составные; API аддона документирует, что праймальные аспекты аддона не поддерживаются.
- **`no_lust` — STARTUP, и значения сторон должны совпадать.** Он меняет сам реестр аспектов, а не
  только контент, поэтому SYNCED-конфиг пришёл бы на клиент уже после регистрации. Расхождение
  клиента и сервера даёт разные ordinal-таблицы и ломает синк `AspectList`; это записывается в README
  как требование к сборке, а не проверяется какой-то магией.
- **`ordinal()` в данных сущности.** `AspectOrb` хранит аспект int-ом. Аддон-аспекты дописываются
  после 48 встроенных в порядке регистрации, существующие значения остаются валидными; все четыре
  строки (`entity/AspectOrb.java:41`, `:54`, `:60`, `:132`) берут индекс из одного источника, и это
  закрепляется game test-ом.
- **Бета-загрузчик.** И NeoForge `26.3.0.57-beta`, и хост двигаются. Меры: пинный sha, громкий
  отказ `prepare_host.py`, полная пересборка хоста занимает около семи минут на этой машине.
- **Порядок регистрации на клиенте и сервере.** Аспект должен существовать на обеих сторонах до
  декода `AspectList`. Мера: регистрация в конструкторе мода, плюс тест, поднимающий выделенный
  сервер и клиент.
- **Поведение без аналога в 1.7.10.** `WandTriggerRegistry`, мутация `ThaumcraftApi.scanEntities`,
  `IScribeTools` заменяются швами хоста, то есть паритет поведенческий, а не по API. Каждая замена
  фиксируется в `docs/deviations.md`.
- **Работа может быть сделана за нас.** 2026-10-20 автор хоста сказал в чате, что намерен сам портировать Forbidden Magic, когда вернётся к проекту. На этот день в репозитории нет ни аддон-контента, ни ветки или issue под FM — то есть ничто не идёт прямо сейчас, но и очередь занята не нами. Мера: точка сверки с автором вынесена в начало работы, до того как написан любой предмет, и её ответ определяет, идём ли мы дальше (план, задача 4b).
- **Визуальная часть не покрыта тестами.** Модели, рендерер Клетки Гнева и иконки аспектов проверяет
  пользователь в `runClient`, по конвенции самого хоста.

## 8. План публикации

1. Разработка идёт против `patches/` локально.
2. Первым, ещё до контента, уходит upstream-запрос: issue в трекере хоста на русском — язык всего
   трекера и `CLAUDE.md` — с описанием потребности в аддон-аспектах, приложенной рабочей серией
   патчей, зелёными прогонами проверок и указанием участия ИИ. В том же сообщении спрашивается, не
   забирает ли автор FM себе, чтобы не делать одну работу дважды. Текст готовит этот проект; отправку
   выполняет пользователь.
3. Если запрос принят, `patches/0001`-`0003` удаляются и порт зависит от релизного хоста. Если
   отказ или молчание — либо остаёмся личным билдом с локальными патчами и распространяем патчер
   (пользователь патчит свой клон и собирает), либо переводим слой аспектов на форму с заменой; это
   решение, а не режим по умолчанию, и оно принимается с числами инкрементов 0 и 1 в руках.

## 9. Существующие порты Forbidden Magic

Проверено 2026-10-20, чтобы отличить свободную нишу от дублирования чужой работы.

`github.com/thaumcraft-port/thaumcraft-addons` — релизная линейка из 32 аддонов, где Forbidden Magic
идёт первым номером в обеих сборках: `0.574-1.20.1-port.0.1.0-20739` (Forge) и
`0.574-1.21.1-port.0.1.0-20740` (NeoForge), требование к хосту записано как
`TC4R ≥ 4.2.3.5 (build 20727)`. Дословно из описания репозитория: «Thaumcraft 4 Reconstructed (TC4R)
附属 / 联动模组的二进制分发与索引», «Minecraft 1.20.1 · Forge», «Minecraft 1.21.1 · NeoForge».

Хост там — **Thaumcraft 4 Reconstructed**, другой проект, не Thaumcraft 4: Reforged: у нашего хоста нет
ветки 1.20.1 вообще, а версия задаётся как `mod_version=1.1`, а не build-номером 207xx. Отсюда:

- FM под хост этого порта не выпускал никто; проект заполняет реальный пробел, а не дублирует;
- сам факт публичной линейки из 32 аддонов к TC4-хосту на NeoForge — внешнее подтверждение того, что
  аддон-аспекты нужны не одному моду. Это аргумент в upstream-запросе (секция 8), более сильный, чем
  «нам не хватает ради одного мода».

**Что показал разбор их jar-а** (`forbidden-magic-neoforge-0.574-1.21.1-port.0.1.0-20740.jar`,
889 классов, изучен локально как поведение, без заимствования кода). Хост Reconstructed делает
аддон-аспекты **данными, а не кодом**:

| Их механизм | Как выглядит |
|---|---|
| тип `api.aspect.AspectId`, значение — `ResourceLocation` | `AspectId.of("forbidden_magic:luxuria")`, никакого enum |
| определение аспекта — JSON аддона | `data/forbidden_magic/thaumcraft/aspects/ira.json` = `{"color":"#870404","components":["thaumcraft:telum","thaumcraft:ignis"],"blend":"normal"}` |
| метки предметов и сущностей — JSON-оверлеи | `object_aspects/vanilla_overlays.json`: `{"kind":"item","id":"minecraft:nether_star","mode":"add","phase":"before_inference","aspects":{"forbidden_magic:infernus":8,"forbidden_magic:superbia":8}}`, мишенью может быть и тег (`c:ores/quartz`) |
| исследования — целиком данные | `research/core.json`: категории, записи, флаги (`AUTO_UNLOCK`/`STUB`/`ROUND`), триггеры, страницы |
| набалдашники и стержни — NeoForge DataMaps | `data/thaumcraft/data_maps/item/wand_caps.json` с `material`, `texture`, `craft_cost`, `assembly_mode`, `order` |
| рубильник контента — условие датапака | `neoforge:conditions` своего типа `forbidden_magic:config` c `option: lust_enabled`; то есть `no_lust` живёт как данные, а не как if в коде |
| совместимость с чужими модами — тоже данные | `entity_aspects/twilight_forest.json`, `object_aspects/blood_magic_overlays.json`, `thaumic_tinkerer_overlays.json` — контент BM/TT/Twilight включается только если мод появился, без компиляции против их API |
| лицензия и авторы объявлены в модах | `license="WTFPL"`, `authors="SpitefulFox; reconstruction contributors"`, версия `0.574-<mc>-port.0.1.0-<build>` |

Из этого следует три поправки к плану, и ни одна не меняет инкременты:

1. **Запрос автору хоста формулируется сильнее.** Не «переведите enum в класс, чтобы мы вызвали
   `register()`», а «современный порт TC4 уже делает аддон-аспекты данными, и на этом держится
   публичная линейка из 32 аддонов вместе с Forbidden Magic». Прецедент, а не просьба. Конкретная
   форма (код-реестр, как в секции 4.2, или данные, как у них) — решение автора хоста, наш diff
   остаётся минимальным доказательством необходимости.
2. **Механизм их data-слоя к нам не переносится напрямую.** У нашего хоста нет загрузчика
   `thaumcraft/aspects/*.json`, есть `AspectSync.addRegistrar` и `AspectRegistrar` в коде. Значит
   берём у них поведение, а не реализацию: аспекты регистрируются кодом через наш патч.
3. **Вырезанная совместимость получает лучший вариант, чем удаление.** Условные данные вместо
   компилируемой зависимости: метки аспект-оверлеев для предметов Botania или Twilight Forest можно
   держать в порту как неактивные правила, которые сработают, если мод появится, — и не тянут за
   собой чужой API на сборку. Решается на инкременте 4, где становятся видны costs; в опись 5.2 это
   не отменяет, а дополняет примечанием.

Оговорка про цель. Если задача — просто играть в Forbidden Magic на современной сборке, линейка выше
уже закрывает её jar-ом для 1.21.1, без этого проекта. Порт оправдан как порт именно под
Thaumcraft 4: Reforged, и это надо держать в голове при решении на гейте инкремента 2.

## 10. Позиционирование: форк, а не оригинал

Правовой слой этим закрывается. Оригинальный Forbidden Magic распространяется под WTFPL, где право
копировать, изменять и распространять дано прямо, — разрешения автора на порт не требуется. Сам порт
распространяется под MIT; WTFPL оригинала и All Rights Reserved хоста не переписаны, а зафиксированы
в `NOTICE`. Правила площадок требуют сверх лицензии только не выдавать производное за оригинал и не
копировать чужие реализации; это выполняется формой, а не словами, и форма фиксируется здесь.

| Что | Значение | Зачем |
|---|---|---|
| modId | `forbiddenmagic` | оригинал 1.7.10 шёл как `ForbiddenMagic`; отдельный id делает коллизию невозможной и сразу читается как другой артефакт |
| displayName | `Forbidden Magic (Reforged Port)` | слово «Port» в самом названии, а не только в описании |
| version | `0.574-26.3-port.0.1.0` | базовая версия оригинала + MC + суффикс порта; та же схема, что у соседнего порта FM |
| authors | `SpitefulFox (original); MxxFoxx2 (port)` | оригинальный автор первым |
| credits | notlikethiss (Thaumcraft 4: Reforged); Azanor (Thaumcraft 4.2.3.5) | цепочка источников видна в модалисте, а не в сноске |
| description | «неофициальный порт/форк Forbidden Magic 0.574 для Thaumcraft 4: Reforged», плюс строка об участии ИИ в разработке | модерация площадок и честность перед игроком |
| `LICENSE` / `NOTICE` | MIT для кода порта; в `NOTICE` — WTFPL оригинала, ARR хоста, происхождение ассетов и темп поддержки без обязательств | лицензия порта — MIT (решение пользователя); лицензии источников не переписаны |

Ассеты и проверимость. В jar порта переходят 135 текстур FM и семь текстур аспектов, причём
аспектные кладутся в собственное пространство имён (`forbiddenmagic:textures/aspects/*.png`), а не в
`thaumcraft:`. Ресурсы и классы хоста в наш jar не попадают ни при какой форме сборки, и это
проверяется машиной, а не внимательностью: `tools/check_provenance.py` падает, если в артефакте
порту найдён путь `assets/thaumcraft/**` или класс вне `dev.visfox.forbiddenreforged.**`, `docs/**` и `tools/**`.
Эта проверка стоит в гейте каждого инкремента наравне с `build` и `runGameTestServer`.

Обратная сторона «форка», о которой надо знать заранее. Позиционирование снимает вопросы площадок, но
не снимает вопрос установки: сборка требует хост `1.2` с аддон-аспект-API, а такого релиза нет, пока
его не примет автор хоста. Это не скрывается, а называется в примечании к релизу первой строкой, и
именно поэтому в гейте инкремента 5 стоит проверка отказа загрузки против неподдерживаемого хоста
(секция 11). И публичный форк порождает обязанность, которой нет у личного билда: вырезанный контент
Blood Magic, Botania, AM2 и Thaumic Tinkerer должен быть перечислен в README раздела «Чего в порту
нет», потому что молча отсутствующая механика читается игроком как баг и превращается в issue-заявки,
которых никто не заказывал. `docs/roadmap.md` для этого и существует — его публичная версия является
частью релиза, а не внутренним документом.

## 11. Форма поставки и объём обязательств

Вывеска «as is» не используется: она юридически почти ничего не даёт (бесплатный мод под WTFPL,
площадки сами сняли с себя ответственность), а по действию вредит — читается как «автору всё равно»,
отпугивает единственную аудиторию, ради которой порт и выкладывается, и задаёт неверный тон в контакте
с maintainer'ом хоста, у которого спрашивают API. Обязательства вместо этого формулируются тремя
конкретными строками в README и примечании к релизу:

1. **Поддерживаемый диапазон.** «Работает с Thaumcraft 4: Reforged `1.2` и новее на Minecraft 26.3;
   другие версии не проверялись». Граница проверяемая, а не общая оговорка.
2. **Чего нет и почему.** Публичная версия `docs/roadmap.md`: вырезанная совместимость по мод-причине,
   ещё не перенесённый контент §5.1 на момент релиза, `plans.txt` как не цель.
3. **Темп.** «Личная инициатива, регулярных обновлений не обещаем; баг-репорты полезны, фикс по
   возможному времени автора». Это ровно то, что хотел сказать AS-IS, но без тона, который стоит
   установок.

Две вещи при этом гарантируются явно, потому что стоят дёшево и ровно они определяют, придёт ли к
тебе игрок с багом или с неразберихой:

- **порт не повреждает сохранение** — отсутствие предмета из-за вырезанной совместимости не должно
  чистить чанки, ронять загрузку мира или молча стирать слоты бижутерии; поведение при неизвестном id
  остаётся ванильным (предмет пропал из стека, мир открылся), а не нашим специальным кодом;
- **порт не стартует против неподдерживаемого хоста** — `FmAspects` до первой регистрации аспектов
  проверяет доступность API и отказывает с читаемым текстом вместо `NoSuchMethodError` со
  стектрейсом. Это единственная настоящая замена дисклеймера: она превращает «неизвестная
  несовместимость» в «известное условие».

Настоящий AS-IS остаётся ровно там, где он честен: серия `patches/` не обязана переживать каждое
обновление `main` хоста, и это написано в `docs/upstream.md` рядом с `host.sha`. И второй случай, где
формулировка accurate: если jar в итоге никуда не выкладывается, публичного артефакта нет, а значит и
обязательств перед установщиками нет никаких.

Канал выпуска — релиз на GitHub (jar, README, `roadmap.md`, `deviations.md`), а не CurseForge или
Modrinth. Площадка навязывает социальный контракт — комментарии, «когда под 26.4», ожидания
совместимости, — который противоречит пункту 3 и стоит дороже, чем вся остальная документация проекта.
Появление на площадках — отдельное решение с отдельной ценой, а не продолжение по умолчанию.
